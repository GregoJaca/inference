# Inference Audit

**Same GPUs, more tokens. We find the problem, fix it, prove it on your traffic.**

Problem: self-hosted inference runs on default / hand-tuned config. GPUs wait on the server; config isn't optimal for your traffic; quantization breaks the speed-up or degrades tool calls.

Examples: 
- a badly quantized MTP (multi-token-prediction) was right 15% of the time and became right 49% of the time after the fix, which took decoding from 112 to 200 tokens/s. [V4 Flash NVFP4](https://huggingface.co/Rarri/DeepSeek-V4-Flash-0731-NVFP4) 
- MTP is worth it at low concurrency, 10% impovement if you choose right. [card](https://huggingface.co/canada-quant/GLM-5.2-W4A16-MTP)
- Giving CPU-starved servers enough cores reduced first-token time 1.47-7.11x. [Georgia Tech](https://arxiv.org/abs/2603.22774) 

Deliver: audit + PR + before/after table (tok/s, TTFT, p99, $/M tokens).

## Pain → fix → proof

| Pain | Fix | Public number |
| --- | --- | --- |
| GPU idle, CPU late (shared box, container limits) | Pin cores, move IRQs, more cores per GPU | Mixed load -20.5% tok/s; pinning +7.6% (1 GPU, 0.6B model) [Eunomia](https://eunomia.dev/blog/2026/05/24/measuring-cpu-noise-in-gpu-inference-with-ebpf/). TTFT 1.47-7.11x with enough cores [Georgia Tech](https://arxiv.org/abs/2603.22774) |
| Settings ≠ traffic | Replay + search flags, GPU split, batch, cache | ≤1.7x vs manual, vendor claim [AIConfigurator](https://docs.nvidia.com/dynamo/latest/performance/aiconfigurator.html). p99 1.36 → 0.70 s, toy model [SLO-Tuner](https://arxiv.org/abs/2603.11340) |
| Quantization breaks draft head | Keep head BF16, list it in ignore | Head accepted 15% → 49%; 112 → 200 tok/s [V4 Flash NVFP4](https://huggingface.co/Rarri/DeepSeek-V4-Flash-0731-NVFP4) |
| Model has no draft head | Train EAGLE-3 on customer traffic | 1.5-2.5x latency [Baseten](https://www.baseten.co/blog/how-to-train-custom-eagle-3-heads-for-speculative-decoding/). Kimi K2.5 1.69-2.00x [AMD](https://rocm.blogs.amd.com/artificial-intelligence/eagle3-speculative-decoding/README.html) |
| Draft accuracy depends on traffic | Measure per prompt type + context; set depth, on/off | GLM-5.2: 28% synthetic vs 46-52% real [card](https://huggingface.co/canada-quant/GLM-5.2-W4A16-MTP) |
| Quantization hurts tool calls | Tool-call + multi-turn tests vs BF16 | Done right: INT4 82.0 vs FP8 82.2 SWE-bench [card](https://huggingface.co/canada-quant/GLM-5.2-W4A16-MTP) |

## Use vs build

| Job | Use (open source) | We build |
| --- | --- | --- |
| Replay load | [GuideLLM](https://github.com/vllm-project/guidellm) | logs → replay converter |
| Search settings | vLLM `auto_tune.sh`, [llm-optimizer](https://bentoml.com/blog/announcing-llm-optimizer), [LLM-Tuna](https://pretalx.devconf.info/devconf-us-2026/talk/9SMF9X/) | search rules, quality gate, rollback |
| Quantize | [LLM Compressor](https://github.com/vllm-project/llm-compressor), [Model Optimizer](https://github.com/NVIDIA/Model-Optimizer) | head-safe recipe per model family |
| Train head | Model Optimizer, [SpecForge](https://github.com/sgl-project/SpecForge), [TorchSpec](https://github.com/torchspec-project/TorchSpec), [vLLM Speculators](https://github.com/vllm-project/speculators) | pipeline: customer prompts → answers regenerated by target |
| Quality | [infer-check](https://pypi.org/project/infer-check/) | tool-call + multi-turn tests; acceptance by prompt type + context |
| Host stalls | [Parca CUDA profiler](https://www.polarsignals.com/blog/posts/2025/10/22/gpu-profiling), cuda\_sched\_trace ([Eunomia](https://eunomia.dev/blog/2026/05/24/measuring-cpu-noise-in-gpu-inference-with-ebpf/)) | thin collector + cause labels |
| Brain | Claude Code (closed) | skills pack, before/after report |

## Client touchpoints

- **Logs:** traffic, arrival time, in/out tokens, streaming, tool calls. No prompt text.
- **Config:** launch command, engine version, k8s/Slurm/Docker files.
- **Metrics:** vLLM `/metrics` (Prometheus).
- **Shell:** read-only on 1 box; root for host tuning.
- **Box:** spare server or time window for before/after.
- **Quality:** their tool schemas + eval set, if any.
- **Prompts:** only to train a head; stay on their machines; DPA if EU.

Gap: found no one verifying draft head + tool calls on the customer's own traffic and load.
