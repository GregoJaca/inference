# Quantization + MTP Head improve

**Quantize without losing speed or capabilities. We check the draft head and tool calls on your traffic and fix what breaks.**

Problem: quantization degrades model performance. there is no widely used solution to prevent deterioration of the speculative head, which can make decoding slower after quantization.

Deliver: quantize or verify your model, keep or build its MTP head, and test on your traffic with a before/after report. recipe (specific to your traffic) + numbers (acceptance by prompt type, tok/s, drift vs BF16, tool-call pass rate).

## Failures → evidence

| Failure | Evidence |
| --- | --- |
| Head dropped on save | `transformers` silently drops `mtp.*`: 15/15 tensors lost. Wrong name in exclude list: server crash-loops, build says OK [Qwythos](https://huggingface.co/PassingByPixels/Qwythos-27B-v1-NVFP4-MTP) |
| Head wrong format | V4 Flash NVFP4: accept 15% (net slowdown) → 49.4%; 112 → 200 tok/s (1.78x) [build](https://huggingface.co/Rarri/DeepSeek-V4-Flash-0731-NVFP4) |
| Head precision | V4 Flash: FP8 head 3.51 vs BF16 4.09 tok/step. Kimi K2.5: FP8 head 1.76-2.00x vs BF16 1.69-1.90x [AMD](https://rocm.blogs.amd.com/artificial-intelligence/eagle3-speculative-decoding/README.html). Opposite results → test per model |
| Calibration | Skip rare experts → fluent but broken model [GLM-5.2 INT4](https://huggingface.co/canada-quant/GLM-5.2-W4A16-MTP) |
| Accuracy depends on traffic | GLM-5.2: 28% synthetic vs 46-52% real. Kimi K2.5 head: 2.34 (humanities) to 3.43 (math) tok/step [NVIDIA](https://huggingface.co/nvidia/Kimi-K2.5-Thinking-Eagle3). 0.949 @2.7K ctx → 0.544 @93.6K [Qwythos](https://huggingface.co/PassingByPixels/Qwythos-27B-v1-NVFP4-MTP) |
| No head / new version | Kimi K2.5: none from Moonshot, NVIDIA trained one (112K prompts). K2.6: new design (EAGLE 3.1) [AMD ATOM](https://rocm.docs.amd.com/projects/atom/en/latest/eagle3_speculative_decoding.html) |
| Train own head | \~100k task prompts, answers regenerated by target, head = 1-5% of params → 1.5-2.5x latency [Baseten](https://www.baseten.co/blog/how-to-train-custom-eagle-3-heads-for-speculative-decoding/) |
| Quality unmeasured | Some builds publish speed only. Done right: INT4 82.0 vs FP8 82.2 SWE-bench [GLM-5.2 INT4](https://huggingface.co/canada-quant/GLM-5.2-W4A16-MTP) |

## Use vs build

| Job | Use (open source) | We build |
| --- | --- | --- |
| Quantize | [LLM Compressor](https://github.com/vllm-project/llm-compressor), [Model Optimizer](https://github.com/NVIDIA/Model-Optimizer) | head-safe recipe per model family: head BF16 + exact module name in ignore list + load check |
| Start from | [NVIDIA NVFP4 V4 Flash](https://huggingface.co/nvidia/DeepSeek-V4-Flash-0731-NVFP4), community builds | verify, don't trust |
| Train head | Model Optimizer, [SpecForge](https://github.com/sgl-project/SpecForge), [TorchSpec](https://github.com/torchspec-project/TorchSpec), [vLLM Speculators](https://github.com/vllm-project/speculators) | pipeline: customer prompts → answers from target model, correct chat template |
| Serve + load | vLLM / SGLang / TensorRT-LLM, [GuideLLM](https://github.com/vllm-project/guidellm) | logs → replay converter |
| Quality | [infer-check](https://pypi.org/project/infer-check/); method per [Fireworks](https://docs.fireworks.ai/models/model-quality) (KL + tool tests) | tool-call + multi-turn suites; acceptance by prompt type + context length |

## Client requirements

- **Model:** model checkpoint they run + how it was quantized.
- **Hardware:** GPU type + count.
- **Logs:** traffic, lengths, timings, tool calls. No prompt text.
- **Tool schemas** + real tool-call examples = what "correct" means.
- **Quality bar:** tasks that must not regress, and by how much.
- **Shell:** test box or spare GPUs; read-only on prod.
- **Metrics + launch command:** engine `/metrics`, serve flags.
- **Prompts + permission:** only to train a head; GPU time for training (ours or theirs).
